vphone Workstation

A friendly desktop manager for your virtual iPhones. It handles the library, settings, and lifecycle — and hands the live device off to vphone-cli, which opens the iPhone screen in its own window.

Standalone SwiftUI app · macOS 15+ Shells out to vphone-cli · no entitlements needed Grounded on main @ 966bddb iOS + cloudOS from restore-info.json v1 · full manager + create wizard
01

The home screen: a sidebar of every VM with its live status, and a detail pane for the selected one. Scan-and-operate, not read top-to-bottom — status reads at a glance from the colored dot, and the primary action is always the big button.

statusLive running/stopped is computed by probing lsof on each VM's Disk.img (the CLI's own truth source) — it isn't in vm list --json, so the app polls it every couple of seconds.
versionsiOS & cloudOS come straight from restore-info.json (surfaced as restoreInfo in vm list/info --json) — recorded on every restore and carried inside vm export, so it's correct even for imported VMs with no IPSW folder. No plist parsing in the app.
variantThe patch variant (regular/jb/exp) isn't recorded by the CLI, so vphone-ws remembers what the wizard used in a small app-owned sidecar; VMs created elsewhere show Unknown until upstream adds it to restore-info.json.
actionsStart spawns vphone-cli vm launch <name>; Stop runs vm stop. Clone/Rename/Delete/Export map 1:1 to CLI subcommands (always with explicit names + --force so nothing prompts).

writesEvery edit goes through vphone-cli vm config — the app never writes config.plist itself, so the CLI stays the single source of truth. CPU/memory work today; the Network control needs a small vm config --network option added to vphone-cli (dovetails with the in-flight bridged-networking work).
timingSettings are editable while the VM is stopped; changes take effect at the next boot, since the VZ configuration is assembled fresh each launch.

honestThe Review step states plainly that creating downloads multi-GB IPSWs, will ask you to authenticate once (for the CFW host-mount), and takes several minutes — then it runs live in the Task console (next screen).
safeYou authenticate through macOS's native authentication dialog — the same system prompt other apps use to make admin changes (Touch ID where available). No password is ever typed into the app, placed on a command line, or written to a log; vphone-ws never sees it. The wizard still blocks early on a nested-VM host, matching the CLI's own guard.
04

Task console

Every long or privileged operation (create, restore, CFW install, export/import) runs here — one place for progress, live logs, and cancellation. Stage chips are parsed from the CLI's === … === banners; the terminal shows the raw stream for anyone who wants it.

cancelCancel forwards SIGINT to the child (the CLI already handles it), and the app watches the child's exit code to mark success or failure — no guessing from log text.
robustThe console is the extensibility seam: any future long-running CLI verb becomes a task here for free.
05

Host readiness

Host prerequisites are the #1 reason a launch fails with a cryptic zsh: killed. This panel checks them up front and, when something's off, says exactly what to run — friendly, not scary. Reached from the “Host ready” pill in the toolbar.

  • Apple Silicon Mac, macOS 15+
    macOS 26.3 · Mac16,12 — supported.
  • Not running inside a VM
    Nested PV=3 guests can't boot. kern.hv_vmm_present = 0 — good.
  • SIP relaxed for research guests
    csrutil configured with allow-research-guests.
  • AMFI allowlist (amfidont) is not running
    Without it, launching the signed VM binary is killed on start. Start the helper — it must stay running while you use VMs.

06

Design language

Inherits the vphone toolchain's flat, precise, dark-neutral identity — softened for approachability. One blue accent; status color kept separate and meaningful.

Palette

Accent · systemBlue — actions, selection
Good · running, ready
Warn · needs attention
Critical · stop, destructive
Ground · cool near-black

Type — friendly face, technical soul

SF Pro — UI & copy
Approachable, native, non-threatening
SF Mono — logs · paths · values
Research-instrument texture, reserved for data

Principles

Flat surfaces, 1px borders, no busy chrome
Plain-English status before technical detail
Every scary step is explained, never silent
Adapts to light & dark automatically
